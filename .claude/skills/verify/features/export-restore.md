# Export and restore JSON

Settings → Data offers `Output records to JSON`, `Tables (CSV)` and `Restore from JSON…`. Export writes the user's history out through the system file exporter; restore reads a JSON file, shows a centered card with a summary (backup date, days covered, row counts, balance after) and asks before replacing history. The backup (schema version 12, restore reads 3–12) carries the journal entries, the whole library, the greeting's name and each day's recovery mark.

## Sub-features

- `exp-json` export history as JSON (`LifeRPG-<day>.json`, `schemaVersion` 12; `dailyContexts[].isRecovery` marks a [recovery](./recovery.md) day (12); the library is one `fullLibrary` block: every quest and routine under its own id with its edits, stamps, archived mark and `starterKey`, and none of the old `library` / `userLibrary` / `libraryChanges` blocks; `profileName` holds the name from Settings → You, cleaned, and is absent when none was given).
- `exp-name` a restore writes the backup's `profileName` only onto a phone that has no name yet (it also marks the name as asked, so the fallback sheet does not appear); a name already on the phone is kept (`UserProfile.restoredName`, Core-tested). Driven 2026-10-12: export with the name `Ada`, `V up --fresh`, `Skip` on the name sheet, restore → `V pref profile.name` reads `Ada` and `profile.asked` `true` (read after `V relaunch`), and the greeting says `Ada`.
- `exp-csv` export tables as a CSV folder (`LifeRPG-tables-<day>`) holding `history-<day>.csv`, `ratings-<day>.csv` and `comments-<day>.csv`.
- `exp-restore` pick a JSON, see the card `Replace all history?`, confirm `Replace everything`; balance, ratings, routines and journal entries equal the source's. `Not yet` or a tap on the dim leaves the store alone.
- `exp-reinstall` the acceptance round trip: export, reinstall (`V up --fresh`), restore. The exported file sits in the simulator's Files, which an app uninstall does not touch.
- `exp-error` a refused file shows a banner in the Data section prefixed `Import failed: ` (from the source, not driven: `This file isn't a Life RPG export.`, `Exported by a newer build (schema N). Update the app first.`, `This export predates import. Export again with this build.`, `Import cancelled, nothing changed: …` when the audit finds a problem and rolls back); a failed export shows `Export failed: …`.

## How to get to it (user POV)

- Settings tab → Data section (below `Journal & reminders`; that page has no export or restore rows).

## Driving it with the simulator

Preconditions: `V up --fresh`, then complete one quest so there is history to carry, and write a journal entry ([journal-editor](./journal-editor.md)). Note the balance B1, the ledger and rating counts, and `V sql "select count(*) from ZJOURNALENTRY"` (E1).

- **Open Settings.** Tap the Settings tab (x=340, y=880). The Data rows are below the floating bar at the top of Settings; one swipe from 760 to 100–150 reaches the bottom, and once the scroll has settled they sit at about y = 234 (`Output records to JSON`), 308 (`Tables (CSV)`), 382 (`Restore from JSON…`) and 456 (`Erase all records…`), measured again 2026-10-12. A tap right after the swipe lands on a page still moving (on 2026-10-12 `Restore from JSON…` was at 657 at that moment), so take `V shot` before tapping.
- **Export.** Tap `Output records to JSON`; wait 5 s, the system file exporter opens on `On My iPhone` with `Save as LifeRPG-<day>`. The saved file can be read from the host to check its content: `find ~/Library/Developer/CoreSimulator/Devices/$(V udid)/data/Containers/Shared/AppGroup -name 'LifeRPG-<day>*.json'` (driven 2026-10-12: `schemaVersion` 12, `profileName` `Ada`, `dailyContexts[0].isRecovery` false). Tap `Save` (about 385, 104). If a file of that name is already there (earlier runs leave `LifeRPG-<day>.json` in the simulator's Files), `Replace Existing Item` appears: choose `Keep Both` (about 220, 558) — the new file is `LifeRPG-<day> 2.json` — rather than overwrite a snapshot someone else made.
- **Change the state (same install).** Spend or earn something so the balance differs from B1 (for example redeem a reward, see [rewards](./rewards.md)).
- **Restore.** Tap `Restore from JSON…`; the picker opens on Recents (newest first; an earlier run opened it on Browse → On My iPhone, the last location used, so read the screenshot). Tap the file you saved (about 77, 245 pt for the newest; check the time and size shown under its name: the 52-entry backup was 172 KB, a day of history plus the library 46 KB). A centered card appears: `Replace all history?`, `Backup exported <date> at <time>, covering <first> – <last>.`, a counts line (`170 quests, 110 routines, 1 ledger entry, 60 ratings, 0 comments, 0 rewards.`, which has **no journal count**; each noun is singular at 1 since the copy pass of 2026-10-12), `Balance after restoring: <B1>.`, and for a schema 9+ file `The library is replaced too: 108 quests and 19 routines` on the starter library (77 / 20 on the old CSV seed) (`, N of them deleted (kept under Archived)` when there are any), `Replace everything` and `Not yet`; the floating tab bar is hidden. The line `Everything in this app's history is replaced by the backup.` is gone, and `(s)` plurals are real plurals. Tap `Replace everything` or `Not yet`: the old positions (588 with the library line, 563 on the shorter card of an older file, `Not yet` 652) assumed that extra line, so read them from a screenshot. `V ledger` returns B1, the other counts match the card, and `select count(*) from ZJOURNALENTRY` returns E1.
- **Library round trip (driven, schema 9).** Rename a seed row in the Library ([library](./library.md)), `V sql` a fingerprint of both library tables (`group_concat(hex(ZID)||ZTEXT||ZDIFFICULTYRAW||ZISACTIVE||ZISARCHIVED||ZORIGINRAW, '')` over rows ordered by text), export, `V up --fresh` (the library comes back as the starter library's 108 quests and 19 routines with new ids, the original wording included; the numbers in this paragraph were observed on the author's earlier CSV seed of 76 and 20), restore: the fingerprint is identical to the one before the export and the 77th row (a quest added with `+`) is back. An export file is 28 KB for this library and no history. Driven again with a deleted row, a row added with `+`, a changed routine schedule and difficulty, a reward, a journal entry and a negative balance (`V day 4` left penalties): the card read `17 quests, 15 routines, 32 ledger entries, 1 ratings, 0 comments, 1 rewards.`, `Balance after restoring: -99.` and `The library is replaced too: 77 quest(s) and 20 routine(s), 1 of them deleted (kept under Archived).` (worded with `(s)` on that build) `Not yet` left 76 quests / 1 ledger row / 0 entries untouched; after `Replace everything` the library fingerprint (id, text, tier, schedule, points, active, archived, origin, last-completed stamp) was byte-identical and the counts (1 journal entry, 1 rating, 15 occurrences, 17 daily quests, 1 reward) matched the pre-export ones.
- **Reinstall round trip (driven).** After the export, `V up --fresh`: `V sql` shows 0 journal entries, 0 ratings and the 100-coin grant. Restore the file as above: 52 journal entries, 60 ratings, 110 routine occurrences, 170 quests and balance 100 come back, and the entry written by hand is `done` with its 4 blocks intact.
- **CSV.** Tap `Tables (CSV)`; the same panel opens for a folder `LifeRPG-tables-<day>`. Swipe down from about y=150 to y=800 to dismiss without saving.

## Gotchas

- These are system panels (document picker). They are driven by screenshot like everything else, but the file locations are not stable handles; expect to spend a step finding the saved file.
- The confirmation is a card (`Replace everything` / `Not yet`), not an alert; builds before commit `1f6a520` showed an alert with `Replace` and `Cancel`. Read the buttons from a screenshot.
- Restore replaces the history tables (quests, routine occurrences, ledger, day settings, ratings, notes, rewards). A backup that carries `journalEntries` also replaces the journal entries, and one with a `journal` block (schema 6 and later) replaces the old journal turns; an older backup (before schema 8) leaves the entries alone and converts its old journal turns into entries. The library is replaced too (schema 9 and later): the store's quests and routines are deleted and the backup's put back under the ids they had, so a renamed row is not duplicated by the freshly seeded original, and a row only the target had is gone; a file before schema 9 keeps the library, re-links by text, puts back the user's own rows the store lacks and re-applies the off / on and re-price changes, and its card then adds `N items in the backup aren't in your library.` (`1 item …` for one) and `Your library: …` lines instead of the library line. Only restore on the verify sim.
- A re-run leaves a new `LifeRPG-<day> N.json` in the simulator's Files each time, and `V up --fresh` does not remove them; that is residue of the run and is kept. Pick the right file by its time and size.
- The round-trip numbers are proven by `JSONImportTests` in Core; this recipe proves that the panels and the confirmation appear and the app ends in the same state.
- The simulator's Files and its other apps are shared with any other session driving the same simulator (see the README on one simulator per checkout).
- `Import failed: ` also prefixes raw system errors (a file that cannot be read), not only the four messages above, and `This export predates import…` also fires for a schema 3–8 file that has neither `fullLibrary` nor `library`. The banner is cleared only by a later successful import, not by a new export, so an old `Export failed:` / `Import failed:` line can stay on screen after a good export.
